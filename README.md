# Мягко

Переиспользуемое веб-приложение для выездной химчистки мебели. Клиент выбирает мебель в 3D-калькуляторе, собирает заказ и оставляет контакты. Владелец видит заявку и фото в кабинете, согласует цену и время. Клиент проверяет обновления по той же приватной ссылке.

## Локальный запуск

Нужны Node.js 22 или новее и npm. Для сайта подходят PostgreSQL 16–19 или отдельная управляемая база. Для локальной демонстрации можно использовать входящий в dev-зависимости PostgreSQL, без Docker и внешнего аккаунта.

```bash
npm ci
cp .env.example .env
```

В `.env` укажите собственный `OWNER_BOOTSTRAP_PASSWORD` длиной 12–128 символов. Для тестов на вымышленных данных можно включить `DEMO_MODE=true`. Значение `APP_ORIGIN` должно точно совпадать с адресом, по которому откроете приложение, включая порт.

В первом терминале

```bash
npm run db:local
```

Во втором терминале

```bash
npm run db:init
npm run dev
```

Откройте [приложение](http://localhost:3000/) и [кабинет](http://localhost:3000/cabinet). База локального PostgreSQL находится в `.data/postgres` и переживает перезапуск. Если используется своя база, задайте её `DATABASE_URL` и пропустите `db:local`. Повтор `db:init` проверяет структуру и сохраняет существующий пароль. После создания владельца уберите `OWNER_BOOTSTRAP_PASSWORD` из рабочего окружения. Для смены используйте «Доступ».

```bash
npm run typecheck
npm test
npm run build
npm start
```

Браузерные проверки требуют отдельного тестового экземпляра и вымышленных данных. После `npx playwright install chromium` задайте `TEST_BASE_URL` и `TEST_OWNER_PASSWORD`. По умолчанию браузерный тест обращается к `http://localhost:3037`. Для проверки PWA запустите production-сборку и установите `TEST_PWA=1`. Интеграционные тесты создают и меняют заявки, временно меняют настройки и пароль. Для них используйте отдельную базу.

## Расчёт

1. Базовый тариф применяется к одной единице. Для матраса с двух сторон базовая стоимость умножается на `1 + процент второй стороны / 100`.
2. Если выбраны сильные загрязнения, результат умножается на `1 + процент загрязнений / 100`.
3. Цена одной единицы округляется до целого рубля математически. Затем умножается на количество.
4. Сервер суммирует позиции с тарифом. Если сумма ниже минимальной стоимости чистки, добавляется разница. Выезд за город прибавляется отдельно.
5. «Другое» требует описания и хотя бы одного фото на заявку. В заказе только с ручной оценкой показывается «По фото», а доплата за выезд оформляется отдельной строкой. В смешанном заказе показываются рассчитанная часть, её доплата до минимума и число предметов «По фото». При согласовании мастер учитывает ручные позиции при пересчёте минимума.

Заявка хранит состав, рассчитанные суммы, настройки тарифа, режим и условия игры на момент отправки. Сервер применяет актуальный на тот момент тариф и игнорирует сумму, присланную браузером. Размер и тип варианта меняют тариф, а сцена иллюстрирует категорию. Пожелания даты и времени интерпретируются по местному времени компании, подтверждение вводит мастер.

## Хранение и доступ

- Заявки, история, настройки, сеансы и сжатые WebP-фото хранятся в PostgreSQL. Для каждого заказчика шаблона создайте отдельный экземпляр и отдельную базу.
- Сохранение заявки, прикрепление фото и запись ключа повторной отправки выполняются одной транзакцией. При потере ответа повтор с тем же ключом возвращает прежнюю приватную ссылку. После удаления заявки хранится только хеш ключа, чтобы повтор не восстановил удалённую заявку.
- Фото проверяются по фактическому формату и декодированию. Ограничения при приёме — один кадр, до 4 МиБ на HTTP-запрос, до 40 мегапикселей, до трёх снимков. Браузер может уменьшить исходник до 24 МиБ перед отправкой. Сервер сохраняет WebP до 1600 px по длинной стороне и удаляет метаданные.
- Черновик полей и корзины хранится в localStorage. Фото черновика сохраняются в IndexedDB и временно в базе. Через 24 часа фото нужно загрузить повторно. С очисткой данных браузера или на другом устройстве локальный черновик недоступен.
- Владелец открывает фото через защищённый маршрут. В клиентском представлении нет адреса, телефона, фото и рабочей заметки владельца. Приватная ссылка с 256-битным токеном даёт доступ к составу и статусу любому, у кого она есть. Не публикуйте её и исключите такие URL из сторонней аналитики и журналов обратного прокси.
- Вход защищён хешем scrypt, HttpOnly cookie и ограничением частоты. Смена пароля закрывает прежние сеансы. Мутации проверяют Origin. Для защиты от распределённого спама используйте ограничения своего прокси или хостинга.
- `npm run db:maintenance` удаляет истёкшие временные фото, сеансы и счётчики. Запускайте её ежедневно отдельно от приложения. Для рабочих заявок установите срок хранения по процессу компании. Удаление записи из кабинета каскадно удаляет фото из рабочей базы.

## Адаптация для компании

| В кабинете | В исходниках |
|---|---|
| Тарифы, минимум, доплаты, город, территория, контакты, акцент | Логотип и PWA-иконки, полная палитра, тексты, политика, типографика |
| Режим игры, сумма бонуса, срок и минимум следующей чистки | Замена моделей, постеров или изменение механики игры |
| Подготовленный характер персонажей, лица и реплики | Новые фразы или характеры, категории и правила расчёта |

Перед передачей заполните название, сведения об операторе и проверенные контактные каналы, обновите текст политики под фактическое хранение и процесс обработки, поменяйте пароль, отключите деморежим и удалите вымышленные заявки из рабочего экземпляра. При отсутствии телефона, почты и Telegram кнопка ведёт к рабочей форме.

## Публикация и расходы

Приложение использует Node.js runtime, PostgreSQL через TCP и Sharp. Подойдёт Node-хостинг или serverless-платформа с полноценным Node runtime и внешней PostgreSQL. В опубликованной версии база должна оставаться доступной независимо от перезапуска приложения. Включите HTTPS на домене, задайте `APP_ORIGIN` с точным HTTPS-адресом, безопасно передайте `DATABASE_URL`, выполните `npm run db:init` и соберите приложение. Для управляемой базы настройте SSL и строку подключения по документации провайдера. Для serverless используйте пулер провайдера и малый `DATABASE_POOL_SIZE`. Обратный прокси должен принимать запрос фото до 4 МиБ и перезаписывать IP-заголовок, если включён `TRUSTED_IP_HEADER`. Без доверенного IP-заголовка посетители делят лимит.

Для продажи шаблона считайте отдельно адаптацию бренда и контента. Регулярные расходы включают домен, выполнение Node-приложения, PostgreSQL, хранение фото и резервные копии, а с ростом трафика — передачу данных и обслуживание. Фото находятся в базе, поэтому учитываются в её объёме и бэкапах. Отдельный аккаунт Figma, Blender и платный LLM для работы сайта не требуются.

## Границы этой версии

- Один владелец, одна компания и одна база на установку. Оплаты, CRM, роли, уведомления, расписание мастеров и новые услуги — отдельные доработки. Владелец смотрит новые заявки в кабинете.
- Игра работает на диване при наличии WebGL2. Прогресс живёт в текущей вкладке. Один код фиксируется на заявку, применяется владельцем к следующей чистке после ручной проверки. Автопогашение и античит отсутствуют.
- В офлайне PWA показывает отдельный экран. Отправка заявки и сверка статуса требуют подключения. Приватные страницы и API не попадают в кеш PWA.
- В рабочем браузере расчёт и форма доступны при сбое 3D или без WebGL2. Для визуального шаблона есть [редактируемые экраны](design/myagko-screens.svg) и [сценарий импорта слоёв в Figma](design/README.md).
- [Лицензии и пересборка 3D](ASSETS.md). Экспорт GLB, постеры и Blender-файл входят в поставку. Продукт работает с готовыми ассетами.
